# Assets du jeu et commerce entre ressources différentes

Les seize PNG fournis dans assets-dev sont conservés sans modification. scripts/prepare-assets.py prépare 25 dérivés WebP (neuf planètes avec miniature de carte, six insignes et un logo), environ 1,86 Mo au total. Le nom source elysl_aurite.png est associé à elys_aurite.webp. Logo Galaxy Simulator dans l’accueil et la navigation ; illustrations par combinaison race/ressource dans les planètes et la carte ; insignes dans les traits planétaires, les ressources commerciales et l’aide. Aucun asset n’est généré pour remplacer les images fournies.

Blocs commerciaux : un rectangle jaune par unité engagée ; chaque centaine complète devient un rectangle orange placé avant les unités restantes. Aucun chiffre ni légende explicative visible dans les blocs. Les capacités libres du partenaire restent vertes. Les disponibilités du monde contrôlé ne sont plus montrées dans la colonne gauche des liaisons ; elles restent accessibles dans le résumé général. Les quantités exactes sont décrites pour les lecteurs d’écran. Le sélecteur affiche nom, disponibilité, civilisation et insigne de ressource.

Le commerce exige des ressources différentes. Le tableau commercial filtre les destinations avant la sélection des quinze voisines. Le serveur refuse aussi une création ou réactivation incompatible, y compris par appel direct. La migration règle d’abord les revenus écoulés, ferme les anciennes liaisons incompatibles puis libère leurs réservations. Trois anciennes liaisons de même ressource ont été fermées ; les trois compatibles restent actives. Aucun revenu acquis n’est repris et les capacités construites du joueur sont conservées.

galaxy_map conserve les noms anonymes, tags et coordonnées de galaxy_signals, et ajoute une clé d’apparence issue de la race et de la ressource. L’apparence devient publique comme demandé pour les illustrations de carte ; aucun propriétaire, effectif militaire ou renseignement démographique n’est ajouté. La projection historique reste compatible.

Tests SQL en rollback : refus des ressources identiques, échanges compatibles, filtrage des destinations, clés d’apparence, absence de propriétaire/forces dans la carte et refus anonyme. Les tests de modification de liaison utilisent désormais des ressources déterministes. Tests Node des blocs aux frontières 99/100/103/199/200, sans chiffre visible.
